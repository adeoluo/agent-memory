# Data Card: synthetic multi-session dialogue benchmark

## Source
Generated by `agent_memory.evaluation.dataset.generate_dataset(users, sessions, seed)`. No real
user data is used. The same seed always produces the same dataset (tested).

## Composition (per user)
- **Attributes:** six topic preferences sampled from eight topics (editor, drink, programming
  language, music genre, cuisine, sport, operating system, note-taking app), a home city, and an
  employer.
- **Timeline:** each attribute gets an initial value in the first third of the sessions and, with
  probability 0.35 one change or 0.25 two changes, later updates in random later sessions.
  Sessions are one to four days apart.
- **Turns per session:** the scripted statements due that session, two to four distractors
  (other people's preferences, questions naming candidate values, tentative plans, article
  mentions), one to three small-talk turns, sometimes a mention of a friend's city, all shuffled;
  every user turn is followed by a generic assistant reply.
- **Phrasing:** three initial templates and four update templates for preferences; one each for
  biography.

## Questions
- `current`: the latest value of each attribute. `previous`: the value before the most recent
  change, for attributes that changed.
- 40% of topic questions use a paraphrase of the topic name (for example "coding language",
  "type of food", "physical activity").
- Default benchmark: 12 users x 20 sessions; seeds 7, 8, 9 for testing and 101, 102 for weight
  tuning (disjoint). About 2,940 turns and 155 questions per seed.

## Known biases and limitations
- Statements use a small set of templates that the rule extractor was written to understand, so
  extraction is near perfect; real users are far more varied.
- Questions and evidence share vocabulary except in the paraphrased subset, which favors lexical
  retrieval.
- English only; one user per namespace; no multi-party conversations.
